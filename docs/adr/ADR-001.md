# ADR-001: Papel do Wazuh e Implicações de Licenciamento dos seus Componentes

**Status:** Proposed  
**Data:** 2026-09-20  
**Decisores:** Architect / Builder, Humano  
**Consultados:** Auditor  

---

## 1. Contexto e Declaração do Problema

O Poseidon é concebido como uma plataforma modular de Security Operations Center (SOC). O Wazuh é uma ferramenta madura e amplamente difundida de detecção de ameaças e integridade de arquivos (FIM).

Contudo, acoplar indevidamente o Poseidon ao Wazuh traz dois riscos graves:
1. **Risco Arquitetural:** Transformar o Poseidon em mero frontend alternativo para o Wazuh, limitando sua evolução como correlacionador agnóstico e violando o Princípio Operacional e a Seção 1 da Constituição.
2. **Risco Jurídico / Licenciamento:** O ecossistema Wazuh divide-se em componentes com licenças distintas (`GPLv2` no Core/Manager/Agent, `Apache 2.0` no Indexer Core, e `AGPL-3.0` em `wazuh-indexer-plugins`). A inclusão indevida de binários, linkagem estática/dinâmica ou modificação de código AGPL-3.0 poderia desencadear efeitos de cópia (copyleft) sobre o código proprietário do Poseidon.

## 2. Decisão

1. **Papel de Fonte Externa:** O Wazuh é classificado exclusivamente como um **motor externo de detecção e fonte de telemetria**, operando no mesmo nível que o Collector Agent próprio ou futuros conectores de EDR.
2. **Isolamento de Camada (Adapter Pattern):** Toda interação com o Wazuh ocorre estritamente dentro da pasta `integrations/wazuh/`. Nenhum arquivo do Core do Poseidon referencia detalhes internos ou formatos proprietários do Wazuh.
3. **Consumo Exclusivo via Rede (REST API / Indexer):**
   - O Poseidon interage com o Wazuh Manager via HTTPS REST API (porta 55000) com autenticação JWT.
   - Os alertas de detecção são consumidos diretamente da API do Wazuh Indexer (porta 9200) ou via streaming de `alerts.json`.
   - Essa comunicação cliente-servidor através de protocolos de rede padronizados **não constitui obra derivada** sob a GPLv2 ou AGPLv3.
4. **Proibição Total de Fork do Dashboard:** Em estrito cumprimento à **Lei 3**, nenhum arquivo do `wazuh-dashboard` é introduzido no repositório. A UI do Poseidon é um SPA React autônomo.
5. **Cluster Próprio de Persistência:** O Poseidon manterá seu próprio cluster OpenSearch 2.x upstream (Apache 2.0) para armazenamento de dados correlacionados, evitando dependência e riscos associados aos plugins AGPL-3.0 do Wazuh Indexer.

## 3. Alternativas Consideradas

### Alternativa A: Forkar o `wazuh-dashboard` e embutir os módulos do Poseidon como plugins OpenSearch Dashboards
- **Vantagens:** Aproveitamento imediato de visualizações pré-existentes do Wazuh.
- **Desvantagens/Motivo da rejeição:** Violação expressa da Lei 3. O dashboard do Wazuh sofre quebras a cada versão upstream, amarra a UI ao ciclo de releases do Wazuh e contamina o frontend com licença GPLv2/AGPL.

### Alternativa B: Embutir o Wazuh Agent ou bibliotecas C do OSSEC no Collector Agent do Poseidon
- **Vantagens:** Reuso de decoders e regras C nativas no endpoint.
- **Desvantagens/Motivo da rejeição:** Violação da Lei 8 (Collector Agent deve ter superfície mínima, código Go assinado e auditável) e contaminação total por GPLv2 da codebase do agente.

### Alternativa C: Integração desacoplada via Adapter e API REST (Escolhida)
- **Vantagens:** Preserva a neutralidade constitucional do Poseidon, garante compliance jurídico e viabiliza a convivência de múltiplas fontes de telemetria (Sysmon, Defender local, Wazuh).
- **Desvantagens:** Exige esforço de desenvolvimento do adaptador e normalizador de eventos na Fase 9.

## 4. Consequências

### Positivas
- Total conformidade com as Leis 1, 3 e 4 da Constituição.
- Nenhuma contaminação por licenças copyleft (`GPLv2` ou `AGPL-3.0`).
- Facilidade de deploy: o usuário pode apontar o Poseidon para um Wazuh existente ou operar sem Wazuh caso use apenas o Collector Agent.

### Negativas / Riscos / Dívidas Assumidas
- O conector precisa lidar com rotação de tokens JWT do Wazuh Manager e monitorar a integridade de índices no Indexer.

### Neutras / Impacto no Roadmap
- Consolida a posição do Wazuh no roadmap: Fase 9 (segunda fonte de eventos, após o Collector Agent na Fase 5).

## 5. Conformidade Constitucional

- [x] Lei 1 — Fontes de licenciamento e APIs checadas com URLs oficiais e datas.
- [x] Lei 2 — Não inventamos schema; dados do Wazuh são normalizados para OCSF/STIX.
- [x] Lei 3 — Não forkamos o `wazuh-dashboard`.
- [x] Lei 4 — Wazuh entra na Fase 9 como segunda fonte, validando que o modelo de evento não foi moldado a ele.
